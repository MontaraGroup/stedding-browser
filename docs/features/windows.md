# Feature: One sidebar for every window

Status: **G0, G1, G3–G6 built** (G6 not yet tried on a real build); **G2 a gap** (BACKLOG S-94); **G7 partial**: written 2026-10-18, tests not yet run (an app's window edge to edge); **N4, N5 built** (their tests since 2026-10-18); **N1–N3, N6–N9 partial** (N1, N2, N6: no Windows CI and the port proper, BACKLOG S-49, S-56; N3: its window class unconfirmed, BACKLOG S-128; N7: most chords checked by the table alone, and the Ctrl+Tab walk's way out, switcher X3, written 2026-10-18, tests not yet run; N8, N9: one look short, BACKLOG S-129); **N10–N14 built** (N14 not yet tried on a real AltGr keyboard); **N15 partial**: written 2026-10-18, tests not yet run (BACKLOG S-234). G5's `profile_id` is the isolated-session partition name (ADR 0019).
Owner docs: `docs/decisions/0016-space-registry.md`, `docs/PRODUCT.md` §10. Patch: 0036.

A second window shows the same Spaces as the first (their order, names, icons and
colours); essentials and pins stay per window (G2). The Space list
lives in a profile-level registry; each window keeps only its active Space and which of
its tabs is in which Space. A pinned tab is a real tab in one window at a time; showing
it in the other windows as a ghost row is G2, not built yet (BACKLOG S-94).

## Notes

- Routing and the little window ask "which window": the last-active
  normal window that shares the registry; a Blank Window is never the answer.
- This cut shares the Space list, its order and metadata (G1, G3) and keeps a
  window's tabs, pins and essentials per window: a pinned tab is a real tab of the
  window it was pinned in, with no ghost row elsewhere yet (G2). The registry seeds
  itself from the first window's session and merges later windows' Spaces by id,
  so an upgrade loses nothing.
