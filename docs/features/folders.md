# Feature: Folders

Status: **F1–F6, F8, F9, F11–F13, F15–F37 built** (F30–F33 since beta 14, F34 since patch 0063, F35 and F36 since 2026-10-15; F37, and the changes of 2026-10-18 to F4 and F36, not yet tried on a real build, F4 not yet with VoiceOver or Narrator; F17's restart cases tested since 2026-10-18); **F7 partial**: built before, its drops onto a header and a header's refusal of a tab group written 2026-10-18, their browser tests passing on the Mac since 2026-10-19 and not yet tried on a real build (its drop from above a folder, BACKLOG S-232, failed on the installed Windows build of patch 0071); **F10 withdrawn** (cut in patch 0055). **F38 built** 2026-10-20 (a folder in the pinned run), and the change to F4 of the same day, both tested on the Mac; F38's drag to any place in the run or under the line (2026-10-21) seen on the Mac's release build, not yet on Windows.
Owner docs: `docs/decisions/0013-folders-are-a-collection-type.md` (model). Patches: `0008` (the whole feature), `0037` (F12), `0060` (F30–F33), `0062` (F19), `0063` (F19's order, F34), and the defect round of 2026-10-18 (F37, and the changes to F4, F7 and F36), and the round after patch 0071 (F7's drops onto a header and its refusal of a tab group, BACKLOG S-232).

A folder is a named, collapsible container of tabs in the sidebar. Folders nest. A folder is
a collection type in the tab tree, not a tab group, so Chrome's groups keep working and a
folder's membership cannot be overwritten by an outer group (ADR 0013).
