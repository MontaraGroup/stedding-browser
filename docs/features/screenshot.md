# Feature: Screenshots

Status: **C1–C12 built**; C9 to C12 (BACKLOG S-156) not yet compiled or run.
Owner docs: `docs/PRODUCT.md`. Patch: `0014`.

Three shortcuts capture the active tab without a share sheet or an extension: the page
as shown (⇧⌘2), a region the user drags out (⌥⇧⌘2), or the whole document (⇧⌘1).
⇧⌘3 to ⇧⌘6 belong to macOS's own screenshot keys and never reach an application,
which is why the region and full-page captures do not sit on them. The result is a PNG in the
profile's Downloads folder, named after the site and the time, the same image on the
clipboard, and a toast that says so, or says what failed.

On Windows every chord below is the Mac's with ⌘ read as Ctrl and ⌥⌘ as Ctrl+Alt
(Alt+1–9 for the Spaces themselves); the full map is `docs/features/windows.md` N7.

| C9 | A capture's codec work never runs on the UI thread. The DevTools reply's JSON parse and base64 decode, the PNG encode of a visible or region capture, the PNG decode of a full-page capture for the clipboard, and the file write run on the one screenshot writer sequence (thread pool, may block, user-visible, blocks shutdown), as one task per capture: a full page's parse, write and decode are one step, and a visible or region capture's encode and write are one step. Only the clipboard write and the toast come back to the UI thread. | C10 | A capture that does not end in a saved file says so.
