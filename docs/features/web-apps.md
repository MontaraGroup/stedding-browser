Any web page can become an app of its own: a window with no browser around it, an icon in the
Dock or the Start menu, and the session of the Space it was made in. On the Mac this is Safari's
"Add to Dock…"; on Windows it is Chromium's and Edge's "Install page as app…". Stedding builds it
on Chromium's own web apps: a page with an installable manifest installs as that app, any other
page as a "do it yourself" app named in the dialog. Nothing is fetched but what the page itself
names, and no Google service is involved.

What Chromium 156 does and what Stedding changes:

- Chromium's "Install page as app…" (`IDC_INSTALL_PWA`) is in the app menu's Save and Share
  block and works: it installs, moves the page into an app window, makes a Mac launcher
  ("shim") or Windows shortcuts. Stedding words it "Add to Dock…" on the Mac, adds it to the
  File menu and the command bar (one command, `IDC_STEDDING_MAKE_APP`), puts the Dock tile in,
  and opens no Finder window.
- Chromium opens an app window in the profile's shared cookie jar, except the first window
  after the install. Stedding records the jar of the Space the app was made in and opens every
  page of the app there (Wa11–Wa15).
- Chromium's app window, under Stedding's layout, showed its page inside Stedding's card (an
  8 DIP mat around the page). Stedding draws it edge to edge, as Chrome and Safari do (Wa9).
- Chromium puts Mac launchers in `~/Applications/Chromium Apps.localized`, a folder shared with
  any real Chromium. Stedding has its own (Wa7).
- Chromium lets an app take links into its scope from the browser by default. Stedding does not
  until the user turns it on for the app (Wa15).

On Windows everything below is the same except where a row names the Mac (the File menu, the
Dock, the launcher) or Windows (the Start menu). Neither platform gets a chord: Safari and
Chromium have none for it.

## Decisions still the owner's

The code takes the first answer of each.

1. The Mac name "Add to Dock…" and a real Dock tile (the Dock restarts once), or "Make App…" and
   no Dock change.
2. The session rule (Wa11): the app keeps its Space's session (ADR 0025, proposed), or a jar of
   its own (Safari), or always the shared jar (Chromium).
3. The installing tab moves into the app (Chromium's), or stays (Safari's behaviour
   **UNVERIFIED**).
4. Capturing off by default for every app (Wa15), or only for do-it-yourself apps.
5. Every Mac install the user starts adds the tile, the address row's icon included (Wa7).
6. Removing an app removes the tile Stedding added (Wa18; a second Dock restart).
7. "Manage Apps" in the command bar only, or a Settings list of apps too.
8. Rename "Create shortcut…" to "Create Desktop Shortcut…" (not done).
9. Command bar matching through a keywords field (built), or the words in the title.
10. Move existing launchers into "Stedding Apps" at the next rebuild (not done; S-171).
11. The dialog's line (Wa5): "Opens with the session of “Work”." (built), or another wording,
    such as "Signed in as in the Space “Work”.".
12. A Mac app's tile placement (Wa7): right after the last browser, newest first (Chromium's
    rule, built), or after the last of Stedding's app tiles.
13. "Open in Stedding" for a shared-jar page when every Space keeps a session of its own
    (Wa14): a new Blank Window (built), or the active Space, signing the page out.

## Notes

- **How it is built on Chromium.** `IDC_INSTALL_PWA` and `IDC_STEDDING_MAKE_APP` both run
  `web_app::CreateWebAppFromCurrentWebContents(kInstallSite)`, which fetches the manifest and
  falls back to a DIY app when the page has no installable one
  (`FallbackBehavior::kUseFallbackInfoWhenNotInstallable`); on a page that is an app's already
  and offers no install, `IDC_STEDDING_MAKE_APP` runs "Open in <App>"
  (`ReparentWebAppForActiveTab`). After the install,
  `FetchManifestAndInstallCommand::OnInstallFinalizedMaybeReparentTab` records the jar and moves
  the installing tab into the app window, or the app launches at the tab's address when
  `CanReparentAppTabToWindow` says the tab stays (Wa6). The intent picker's launch goes through
  `WebAppUiManagerImpl::ReparentAppTabToWindow`'s callback overload, which asks the same
  question and launches instead. App windows use `BrowserViewAppLayoutImpl`, not Stedding's
  layout, and get no `SpaceModel` or vertical strip. A web app made from a normal page has no
  storage partition of its own in Chromium: only extensions and isolated web apps do
  (`ChromeContentBrowserClient::GetStoragePartitionConfigForSite`).
- **Where the pieces live.** The records: `chrome/common/stedding/web_apps.{h,cc}` (below the
  UI layer, so the install commands can write them), written through
  `chrome/browser/web_applications/web_app_jar_record.{h,cc}`. The jar answers:
  `chrome/browser/ui/spaces/app_jar.{h,cc}`, asked by the navigator (`CreateTargetContents`),
  tab restore, session restore, the reparent rules, "Open in Stedding", navigation capturing,
  the dialogs and the uninstall. The command: `chrome/browser/ui/stedding/make_app.{h,cc}` and
  its rules, `make_app_rules.{h,cc}`. The Dock: `chrome/browser/ui/stedding/app_dock_mac.{h,mm}`
  over `dock::AddIcon` and the new `dock::RemoveIcon`, on the shortcut sequence. The records go
  with the app through `stedding::AppRecordsKeeper`, an install-manager observer the web-app UI
  manager starts, and starts again with a new install manager.
- **Why the Space's session (Wa11), not one of its own.** Safari gives each web app its own
  jar, seeded with the site's cookies when it is made. Chrome and Edge share the browser's.
  Stedding's Spaces already are its way of keeping sessions apart, so an app follows the Space
  it came from: the work Gmail from the Work Space, the personal one from Home. An own-jar
  option ("Keep this app's data separate") can come later; it needs cookie copying, a
  garbage-collection rule and a clearing control (owner decision 2, ADR 0025).
- **Recording the jar, not the Space.** The install command sees only the tab's partition,
  below the UI layer. At launch the jar name is looked up in the Space registry: a Space that
  still keeps it, with its own session on, gives its partition; anything else the shared jar
  (Wa13). A Blank Window's Spaces are not in the profile's registry, so an app made there opens
  in the shared jar.
- **Links from other apps.** A link another app hands to Stedding is the little window's or a
  route's (little E4, routing D3) unless the user turns capturing on for an app (Wa15).
- **Known limit, not new.** macOS screen-share audio does not recognise Stedding's apps as the
  browser: `content/browser/media/capture/desktop_capture_util_mac.mm` lists only
  `org.chromium.Chromium` (`docs/ARCHITECTURE.md`, "Three identifiers do not follow
  `MAC_BUNDLE_ID`").
- **Launchers from beta 8.** Launchers made before the Chromium-to-Stedding profile move are
  not rebuilt onto Stedding's folder (BACKLOG S-171); Wa7's folder change is a good moment to
  rebuild them (owner decision 10).
- **Not to be confused with** BACKLOG S-90 ("Web apps keep their own keys"), which is about
  in-page apps such as Google Docs in a tab.
