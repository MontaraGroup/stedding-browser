# Feature: Dark pages

Status: **Dk12, Dk13, Dk15, Dk17, Dk19, Dk20 and Dk22 built** (Dk17 and Dk20 2026-10-19;
the others' tests, with Dk8's and Dk24's, pass on the Mac on 2026-10-26); **the rest
partial**: written 2026-10-18 (the Mac View menu row of Dk24 and the app window's title bar of
Dk8 on 2026-10-19). Every browser test below that the Mac builds passed on the Mac on
2026-10-19 (`DarkPagesKeysTest` is built off the Mac only, and nothing has run on Windows
yet); the other rows' states are not yet brought up to that run, and nothing has been seen
live yet; each becomes built when its tests pass, Dk7 only once `dk_no_flash_light` passes too, and Dk23 once its cost on a heavy page is
measured (TBD); Dk24's app-menu row is planned (the owner's call). BACKLOG S-100.
Owner docs: `docs/PRODUCT.md` §13 ("Dark mode for web pages", M10), `docs/ROADMAP.md` M10,
`docs/PRIVACY.md`. Patch: 0072.

For night work: one switch turns every website dark, in every window and Space of the profile,
until it is turned off. It is Chromium's own automatic dark mode for web contents, driven by its
existing preference, not an injected stylesheet or a CSS filter: Blink draws bright backgrounds
dark and dark text light at paint time, from a page's first frame. Pictures, video, canvas and
the PDF page keep their pixels; `position: fixed` keeps working; the page's scripts and styles
are not touched. A site with its own dark theme uses it. The switch is a moon button at the
address row's right end, ⌥⇧⌘D, a command bar row, a Settings row and, on the Mac, a View menu
row; it repaints open pages in
place, with no reload. Settings keeps exceptions: "all sites, except these" (the default) or
"only these sites". The browser's own pages, DevTools and extension pages are never darkened.

Against the Arc extension "Dark/Light Mode Toggle" (a CSS invert applied after load): no white
flash before it applies (Dk7, written and not yet measured), images and video untouched (Dk3), fixed elements intact (Dk2), a
live toggle without a reload (Dk6), a global switch with per-site exceptions in both directions
(Dk12–Dk15), a shortcut (Dk18), a command bar row (Dk19) and a Settings entry (Dk20).

On Windows every chord below is the Mac's with ⌘ read as Ctrl and ⌥⌘ as Ctrl+Alt; the full map
is `docs/features/windows.md` N7.

## What it never touches

- The window: its Light, Dark or System mode, the sidebar, the address row's controls, menus, the
  command bar, toasts and the Space colours. The address row's colour follows the page, as it
  always does (Dk8).
- The browser's own pages, DevTools, extension pages, options pages and popups (Dk9).
- Pictures, video, canvas, WebGL, the PDF page, and printed output (Dk3, Dk11).
- The page itself: no stylesheet, script, filter or DOM change; computed styles, layout,
  `position: fixed`, scrolling and timing are the page's (Dk2). The only things a page can see
  are Dk4's `prefers-color-scheme: dark` and the `canvas` colour trick Chrome documents.
- Cookies, storage, history, network requests: none are read, written or made.
- Chromium's forced colours ("Page colours", Windows contrast themes) are left as they are; how
  the two combine is a live check on Windows.

## Privacy

- Dark pages makes no network request and sends nothing anywhere. Chromium counts its use in a
  local `UseCounter`; Stedding sends no metrics, so the counter never leaves the machine
  (`docs/PRIVACY.md`, no telemetry).
- What is stored, and where: the switch and the button's setting in the profile's `Preferences`
  file; the mode and the two lists as the content setting's default and entries in the same file
  (`profile.default_content_setting_values.auto_dark_web_content`,
  `profile.content_settings.exceptions.auto_dark_web_content`). The content setting is marked
  unsyncable, and Stedding has no sync. The lists name sites the user chose, so they are as
  private as bookmarks: they stay on the machine. Registered on desktop, the setting is one of
  those Delete browsing data clears with "Site settings" ticked, and Settings > Reset settings
  clears both lists and returns the mode to "all sites" (read in `browsing_data_helper.cc`
  `RemoveSiteSettingsData` and `profile_resetter.cc`; not yet run).
- Private windows: a site chosen from a private window is held in memory for that session and
  never written to the profile or to disk (Dk21). Changing the switch from a private window
  writes the profile's switch, which names no site.
- What a page can learn: that the reader prefers dark (Dk4), the same signal a dark window already
  gives every page, and, through Chrome's documented `canvas` trick, that automatic darkening is
  on. A site cannot read the lists; an embedded frame follows its top-level site and learns
  nothing about other sites.

  frame in the old state; Android ships that design. Dk7 sends the coming page's decision from

  colour. Whether any frame still shows the old state on screen is `dk_no_flash_light`'s to
  say; the preference update and the commit travel on the renderer's one channel, read in code,
  not measured.

  in 141–149; the classifier changes of 150 that answer most of them are in 156.
